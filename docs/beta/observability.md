# Observability Starter + Error Handling

## Where Logs Live
Logs are written to the terminal where the C++ server is running:

- successful request logs go to standard output
- error logs go to standard error

## How to View Logs

1. Build and run the server locally
2. Send requests to the API endpoints
3. Observe log output in the same terminal session

## What Events Are Logged

The Beta starter logs the following endpoints:

- `GET /api/health`
- `POST /api/students`
- `POST /api/students/{studentId}/assessments`
- `GET /api/students/{studentId}/recommendations/latest`

The logging system records:

- request ID
- endpoint
- action performed
- HTTP status code
- relevant request context

Errors:
- `validation_error`
- `domain_error` 
- `http_error`

## Logged Failure Cases

The following common failures are logged:

- missing required fields
- invalid score validation failures
- unknown `studentId` lookup failures

## Correlating User Actions to Logs

Each request includes a `requestId` value.

This allows a tester to trace a user action to the exact log entry.

Example request flow:
API Request
↓
requestId generated by server
↓
log entry written to terminal

Example:
POST /api/students
↓
requestId=req-2
↓
[INFO] requestId=req-2 endpoint=/api/students status=201 action=create_student studentId=student_1

This demonstrates how a tester can correlate an API request to the corresponding log entry.
