# Data Model (MVP)

This MVP uses **in-memory storage only**. Data resets when the server restarts.
The model is intentionally minimal to support the single demo path:
Create Student → Add Assessment → Generate Recommendation → Optional Teacher Override.

## Entities

### Student
- **studentId** (PK, string)
- name (string)
- gradeLevel (int)

Relationship:
- Student 1—many Assessments
- Student 1—many Recommendations (we use “latest” in MVP)

### Assessment
- **assessmentId** (PK, string)
- **studentId** (FK → Student.studentId)
- skill (string)
- score (int 0–100)

### Recommendation
- **recommendationId** (PK, string)
- **studentId** (FK → Student.studentId)
- activityId (string)
- reason (string)
- source (enum: `rules` | `override`)

## Constraints / Assumptions (Intentional Simplifications)
- No persistence layer (no SQLite/Postgres). In-memory only.
- `studentId`/`assessmentId`/`recommendationId` are generated by the server and unique per run.
- Recommendation logic is rules-based:
  - Example: score < threshold → pick foundational activity; else pick next-level activity.
- Only “latest recommendation” is required for MVP demo; history may exist but not required.
- Auth is placeholder (`X-API-Key` header). No real user identity or permissions.
